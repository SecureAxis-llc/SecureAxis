Linux & Server Hardening

Servers built for attack, not just uptime.

Linux and Windows servers hardened against CIS benchmarks, with patching, access and logging set up so they stay that way.

Discuss Linux & Server Hardening ▸Open in the interactive menu

Who it's for

  • Teams running Linux or Windows servers that were set up to work, not to be secure
  • Organisations that need servers to meet CIS benchmarks
  • Businesses where many people share admin or root access

Problems it helps with

  • Default settings left in place since the server was built
  • Shared admin accounts and SSH keys nobody tracks
  • Servers missing updates because patching feels risky
  • Little or no logging when something goes wrong

Scope and deliverables

An assessment against CIS benchmarks, then hardening, privileged access, patching and logging set up so the configuration stays secure over time.

What we do

  • CIS benchmark assessment for Linux and Windows Server
  • SSH, sudo and privileged access review
  • Patch and configuration management
  • Server logging and audit set-up

What you get

  • Hardening gap report
  • Baseline as code (Ansible or Group Policy)
  • Server access review

How an engagement works

  1. Conversation

    You tell us what's going on and what you need. We ask questions to understand your environment and constraints.

  2. Written scope

    We agree in writing what is in and out of scope, what you'll receive and when, before any work starts.

  3. The work

    Carried out as agreed. Anything urgent is raised with you as soon as it's found, not saved for the report.

  4. Report and walkthrough

    Findings in plain language, ranked by what to fix first, and a walkthrough with your team.

Questions

Which systems do you cover?

Common Linux distributions and Windows Server.

Can the settings be applied automatically?

Yes. Where it suits your team, the baseline is written as code, for example Ansible or Group Policy, so new servers get it by default.

Do you need root access?

Only if you want us to apply changes. An assessment can run with read-only access.
